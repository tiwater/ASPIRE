**必须保留的姿态限制：** v58 的准备工作姿态使用 `dt_joint=+1.018853 rad`，而所引用厂商 URDF 上限为 `+0.17 rad`。该生命周期模型显式用了观测范围扩展，只供离线几何仿真；不代表确认厂商限位错误，也不构成真机轨迹。2026-11-07 的源 URDF 限位内预抓筛选中，`xt_joint_1=-1.5`、`xt_joint_2=+1.5`、其余身体关节为零的候选通过双臂预抓 IK、组合终点及采样预抓通道检查；零姿候选和另外两种候选没有通过。随后对该候选做了 0.01 rad 分辨率的全机器人采样：站立下垂→双臂从两侧抬起→下肢折叠降低→左右臂依次进入预抓位，路径均未发现碰撞；`dt_joint` 始终为 0，上身倾角最大约 0°。这仍只是采样几何与 IK/路径可达性证据，不证明伺服动力学、任务抓取/搬运/倾倒或连续工作流程；原始筛选结果留在本地 artifacts，不随精简协作提交。下一步以此姿态重定向咖啡任务目标并验证端到端仿真；历史真机状态映射/限位冲突仍需只读资料厘清后才能谈硬件迁移。

## 目标与 ASPIRE 的训练含义

任务从壶里已有咖啡开始：右臂取单杯；左臂抓壶柄，向机器人左后方水平退出；
低壶嘴、慢倾倒至杯容量约 80%；放杯；逆向回壶并释放。
不包含按键萃取、加热、底盘自主导航或高保真流体。每回合底盘先固定，回合之间
改变机器人与操作台相对站位；不能将某次真机的全局 XYZ 固化成技能。

当前 ASPIRE 的主机制是 **观察 → 生成/执行 CaP 程序 → 分析失败 → 修正程序与技能
→ 独立验证**。成果首先是策略代码和技能库，而非默认梯度训练的网络权重。
复用 CapApi、ProgramExecutor、感知/规划接口和日志；参考
[iterative-debugging 技能](../../.claude/skills/iterative-debugging/SKILL.md) 的开发/验证纪律。
现成 LIBERO/Robosuite 启动脚本尚不支持这个自定义环境，不能只换任务名称。
采用独立 MuJoCo RealMan 环境，无需强行替换 LIBERO 的默认单臂机器人。

固定 CaP 程序可由执行器运行；若保留 System 2 在线推理、技能选择和恢复，运行时
仍需要 LLM。视觉动作网络或蒸馏策略应在数据与评估链路建立后另列，不混同于本轮技能迭代。

## 判分与液体边界

- 仿真评估器可以读取物体真值/接触/速度，仅用于判分和诊断；不能将真值能力当作
  真机感知。若先做 oracle 几何基线，应与之后 RGB-D 感知策略分别报告。
- 取杯需验证保持、单杯分离及其余杯保留；放杯/回壶需验证释放后的稳定支撑。
  仅夹爪闭合或坐标到位不计成功。
- 不做高保真流体。第一版先评壶嘴在杯沿内、距离低、倾角速度受限、无刚体碰撞。
  如需 80% 指标，增加明确标记的质量守恒体积转移代理；纯姿态成绩不能称作真实
  倒入 80% 或不洒。代理体积、几何姿态、真机液体成绩分开。
- 空壶 396 g、弹簧力按满壶重量一半、杯架力按两满杯水重量，沿用用户批准初值。
  未知参数先做敏感性分析，无需现在全部实测。负载试验已实现等效液体质量/质心/惯量
  及质量守恒转移代理；默认两满杯只改变装水量，不随之缩小出水口弹簧力或杯架卡扣力。
  通用几何模型仍保留干重，当前负载场景由工作负载准备器生成，不能把空壶成绩当装水搬运。
- 真机手眼/定位误差在迁移前作为扰动加入仿真；不必先补完所有真机全局标定，
  才能在仿真内部使用一致的世界/操作台/机器人坐标系。
