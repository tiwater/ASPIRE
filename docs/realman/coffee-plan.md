# RealBot-01 咖啡任务：实施计划与当前边界

更新时间：2026-10-26。对象为 RealBot-01 机身、双 RM75 七轴臂、CTAG2F90D 夹爪。

## 目标与验收对象

右臂从摩擦杯架取出一只杯，左臂抓壶柄，沿机器人左后方水平退出咖啡机，
向杯中倒入约 80% 的可用容量，停止出流，放杯，再沿退出路径逆向放回壶并释放。
本任务从壶里已有咖啡开始，不包含按键萃取、加热或底盘自主导航。
用户已确认按容量的 80%，允许先用几何体积与水密度估计；空壶质量为 396 g。
最新接触力和倾倒初值见 [parameter-priors.md](parameter-priors.md)，标定配合见 [calibration.md](calibration.md)。

本次提供的代码是第一阶段开发底座，**不是已通过真机验收的端到端咖啡策略**。
未发送运动、夹爪、机身或底盘命令；未运行历史动作脚本。

## 模型设计

源模型：`ref/realman_robot/LSRX_V0.0.13.SLDASM/urdf/LSRX_V0.0.13.SLDASM.urdf`。
构建器解析 `package://` 网格路径，给几何唯一名称，保留原始碰撞几何，导出 MuJoCo。
双臂各 7 个电机关节，`l/r_joint_8` 是固定变换；相机支架可调关节不当作电机。
夹爪的 10 个 mimic 关系转换为 equality 约束，两只夹爪各有一个仿真驱动器。
少量刚性装配相邻件的碰撞排除逐对记录在 `build_report.json`，没有全局关闭自碰撞。

当前 workbench 冻结底盘、身体、头部、相机支架在 URDF 零位。
模型中的零位不是当前真机零位；真实控制器角度不能直接填写为模型角度。
可通过场景配置改变机器人底座位置和朝向来研究相对站位，尚无导航/身体运动策略。

`robot.frozen_joints_rad` 也允许在构建时指定身体/头部/支架的 **URDF** 姿态，
例如用 `xt_joint_1`、`xt_joint_2`、`dt_joint` 研究工作高度；构建器先核对关节范围再固定该姿态。
这些角度不是 ROS 控制器命令，不能发送到真机。默认空字典保留原始零位。
当前默认站位只是场景排布，并未验证咖啡任务全程可达；例如零位下对
`[0.55, 0.25, 1.0] m` 的左臂安装末端位置探针仍有约 107 mm 残差。
这表明必须把站位/身体工作姿态选择纳入迭代，不能只给夹爪指定物体坐标。

| 对象 | 几何与交互模型 | 仍需测量 |
|---|---|---|
| 操作台 | 有限桌面和桌腿，约 120×60 cm、75 cm 高的照片估计 | 实际桌边、厚度、机器人到桌面的当前变换 |
| 咖啡机 | 后部实体、上部机头、底座、左侧壶位、右侧托盘；前部保留拿壶空间 | 壶位内壁与承托边缘，毫米级接触区形状 |
| 咖啡壶 | 中空玻璃壶、开孔壶盖、带开口的四段把手、壶嘴参考点 | 重心、真实壶嘴、盖孔/斜面和把手尺寸；空壶质量已由用户提供 |
| 弹簧出水口 | 带有限行程和弹性回复的滑动顶头代理 | 接触面形状、行程、预载、刚度、退出/插入力曲线 |
| 纸杯 | 中空锥台分段碰撞壁和底面，口径约 70 mm、杯高约 80 mm 的照片估计 | 可用容量、底径、杯沿、纸杯压缩与摩擦 |
| 杯架 | 底座、后支撑、中空套筒、3 个可退让摩擦触点和 4 只独立杯 | 实际夹持机构、出杯力、杯间嵌套、是否需要抬升/偏移解锁 |

配置：`configs/realman/coffee_scene.json`。每类参数带来源/资格信息。
玻璃、反光塑料和纸杯不宜只靠稀疏照片直接做高置信度碰撞网格，因此先做可调的几何模型。
这不是照片级扫描模型。弹簧/摩擦/质量/壁厚是代理参数；杯架刚度和叠杯间距经过名义仿真稳定性调整，
不是实测结论，不能作为真机力阈值。

不模拟液体、温度、纸杯形变或真实驱动器。当前测试不能证明倒水量、止流延迟、夹持可靠性或出水口落座。
离线 IK 的末端为 URDF `link_8` 安装坐标系，并非夹爪抓取中心；只报告目标位姿残差和终点碰撞，
不证明整条运动路径可执行。仿真关节插值不带全路径碰撞规划。

## 移动机器人如何适配不同操作台

把物体动作目标表示在**当前操作台坐标系**，不保存全局固定 XYZ。
每次底盘或身体位置变化后，重新估计桌面有限区域、咖啡机、杯架和杯子的位姿，
更新 `T_world_table`、全身关节状态及左右工具变换，重新检查可达性和碰撞。
操作过程中先保持底盘静止；需要重新站位时退出当前操作段，保留持物状态并重新定位。

首轮建议胸部深度建立桌面/场景，头部作为补充视角，腕部相机完成把手/杯沿局部对齐。
深度先用自身内参反投影，再用实测 Depth→RGB 外参配准到彩色图；
不要在尺寸不同、未配准的深度图上直接套用 RGB 掩码。
透明壶体深度可能不可靠，应结合不透明把手、壶盖、机器参考面和多视角。

放壶阶段建议增加一个能看到壶底承托边缘、壶盖和弹簧口的斜侧视角。
它用于判断壶体是否倾斜、是否顶住边缘、是否落座。
现有头/胸部图像尚不足以证明该接触区在左臂遮挡时始终可见；具体安装点要在一次覆盖验证后确定。

## 阶段控制与证据

`src/cap_harness/realman/task.py` 保存顺序与判据，未知/过期证据不能推进阶段：

1. **定位**：底盘静止、桌面坐标有效、操作对象身份与位姿成立、杯容量估计可用且来源明确。
2. **取杯**：右手持住单杯、目标杯与杯堆分离、其余杯仍保留。
3. **抓壶**：左手把手接触成立，同时保持右手杯子。
4. **退出**：壶沿左后方水平路径脱离出水口与机体，保持壶直立。
5. **对准**：壶嘴位于杯口内的可接收区域，双臂/物体净空成立。
6. **倒水**：实时估计入杯量，接近目标时计入止流延迟，回倾后确认出流停止、无溢出。
7. **放杯**：杯底受桌面支撑、杯体直立，再释放右夹爪。
8. **回壶**：复用本轮退出的物体路径作为候选逆路径；持续看壶底/壶盖/出水口关系，不能盲目重放旧关节轨迹。
9. **释放**：确认壶稳定落座后释放左夹爪，再验证放手后稳定。

关节到位、夹爪反馈非零、执行器返回 success，均不能替代物体关系的证据。
不把“停留几秒”用作倒入八成的判据，也不把模拟器对象真值作为真机视觉能力。
阶段机尚未连接具体感知检测器和执行后端；目前是可测试的监督契约。

## 真机接入必须补齐的内容

1. **坐标绑定**：左右控制器到新 URDF 的关节顺序/符号/零偏；身体关节映射；
   当前 tool/work frame；左右夹爪抓取中心和开合轴；多姿态验证相机外参。
2. **持物与接触**：各夹爪开口曲线；空壶/杯质量；杯架拔出力；出水口力/位移数据；
   正常接触与卡滞样本。历史“position=200 对应 26.5 mm”只作参考点，不能线性推广整个行程。
3. **执行后端**：在 RealMan ROS/控制器之上建立单一命令所有权，明确命令接受与终态完成，
   校验最新起点、身体/底盘上下文，支持原生停止和超时对账，然后注册为 CAP 原生工具。
   不从 shell、一次性历史脚本或 YAM 的六轴接口执行机器人动作。
4. **量与视觉**：先用几何体积估计容量，后续量杯复核；验证腕部力/称重信号在不同姿态下的质量估计，
   或增加独立称重/液位观测。历史 165 ml 试验是局部经验，不是当前杯子的八成。

用户已明确容量比例、几何估算方法和空壶重量，并确认没有已验证的标定文件。
下一步先提供标定板类型、格数和实际尺寸，检查只读图像的角点可见性，再按
[标定流程](calibration.md)补齐控制器位姿采集与现场样本。

## 后续策略迭代

先完成可解释的几何/闭环阶段策略，再决定是否需要学习残差或训练视觉模型。
现有 ASPIRE 路线可生成并迭代 CaP 程序，不要求先训练端到端神经策略。
每个开发回合固定代码、机器人配置与模型哈希，保存观测、目标/实际状态、阶段证据和失败类型。
在开发集变化桌面/机器/杯架相对位姿、杯数、初始开口、接触参数与遮挡；
保留独立验证配置，分别统计取杯、退出、倾倒和落座成功率。
仿真通过后仍需阶段性的真机验证；新增实测数据反过来更新模型，不把仿真成功率直接当成真机成功率。
