# RealBot-01 标定配合流程

截至 2026-10-27，左右腕 RGB 手眼均已完成采集、求解和各 4 个独立姿态的局部验证，见
[左腕结果](left-handeye-20261027.md)和[右腕结果](right-handeye-20261027.md)。
头/胸相机已开始共同棋盘多姿态采集，第 1 组质量通过，尚未完成外参验证；
夹爪 TCP 和完整关节映射仍未完成。右腕采样结束后服务已恢复只读。
下文作为后续标定的配合流程；原生低速调试接口可在逐项验收后限定启用。

## 标定板信息

当前使用普通棋盘格：11×8 内角点，方格边长 60 mm；配置已写入
`configs/realman/calibration_board.json`。换板时按以下信息更新：

- 普通棋盘格：横向 × 纵向的**内角点数**、每格实际边长（毫米）。
  例如 10×7 个黑白方格对应 9×6 个内角点。量实际板，不能只相信打印纸标注。
- ChArUco：方格横纵数、方格边长、标记边长、ArUco 字典（最好提供生成配置/型号）。
- AprilTag 或其他板：提供具体标签家族、ID 排列及实际边长；当前预检程序支持棋盘格和 ChArUco，其他板先按规格扩展。
- 确认板面平整、刚性固定，不是手持会弯曲的纸。普通棋盘格在边框标记一个方向，避免不同照片中的坐标原点翻转。

先把板放在胸部深度相机彩色图能完整看到的位置，不挡住机械臂。
这一轮只检查是否能清晰识别、大小是否合适、图像边缘是否清楚，**不需要摆动机器人**。
提供板规格并摆好后，再采新的只读图像；旧场景照片不能代替这一步。

## 分开做四类标定

| 项目 | 现场配合 | 输入与产物 |
|---|---|---|
| 相机内参核验 | 机器人固定，人工改变板的位置/倾角，覆盖中心和四角；同一图像模式 | 新 RGB、CameraInfo、板角点；验证内参/畸变，必要时重标 |
| 腕部手眼（左右分别） | 板固定不动，底盘和身体保持固定；腕部采用不同位置及绕不同轴的姿态 | 同步 `T_base_flange` 和 `T_camera_board`，求 `T_flange_camera` |
| 头/胸相机到机械臂基座 | 相机所依附的头/身体固定；板与法兰刚性连接并记录连接关系；需要受控多姿态 | 固定相机外参；不能把腕部手眼结果直接复制给胸部 |
| 工具与关节映射 | 先核对当前 tool/work frame、控制器关节、URDF/DH；再做限定范围的对应验证；TCP 用刚性参考点 | 关节顺序/符号/零偏、双臂工具偏移和开合轴、特定夹爪开口下的中心 |

标定板不能独自给出机械臂关节零偏、夹爪 TCP 或全身坐标关系。
手眼可先使用经核对的控制器法兰位姿，不必等 URDF 完全标定；但不能用未经验证的
`URDF FK(ROS 关节值)` 冒充法兰位姿，也不能混用控制器左右臂基座。

普通手眼的变换约定是：`T_A_B` 把 B 系点变换到 A 系。
固定板的每组样本应满足：

```text
T_base_flange[i] × T_flange_camera × T_camera_board[i] = T_base_board
```

OpenCV 的 `calibrateHandEye` 对应输入 gripper→base、target→camera，输出 camera→gripper。
仅平移或始终绕同一轴转动不能充分约束解。方法约定见
[OpenCV 官方文档](https://docs.opencv.org/4.10.0/d9/d0c/group__calib3d.html)。

首轮计划每只腕部相机约 15–20 个有姿态差异的开发样本，再另采 5 个验证姿态；
这是采集预算，不是达到张数就自动通过。每个姿态停稳后采集原始图像、角点、
源时间戳、控制器法兰位姿/关节、tool/work frame、身体/底盘上下文和配置版本。
不能只记录命令目标，不能只依赖没有源时间戳的 ROS 状态与图像“差不多同时”到达。

## 动作采集接口

现已提供原生 CAP 关节预览、受门控低速运动、停止、观察及
`cap_capture_handeye_sample`。后者保存停稳的控制器位姿—图像时间夹持记录，
包括原始时间戳和 tool/work frame，属于软件配对而非硬件同步。
运动需事先审查完整路径并保留现场安全条件，不能因为左腕标定完成就放开其他动作。
不要用 shell 发送运动命令，也不要重放历史动作脚本来补样本。
工作区 [AGENTS.md](../../AGENTS.md) 规定：“Act through registered native `mcp__cap__*` tools; never bypass them … with … shell-wrapped motion.”

## 当前可用工具

板规格写入 `configs/realman/calibration_board.json`，未知值保持 null。

```bash
# 只对已采集数据做离线检查；不会访问运动接口。
PYTHONPATH=src .venv-libero/bin/python -m cap_harness.realman calibration-check \
  artifacts/realman/aspire_coffee_capture_20261026_01
```

输出每路相机的图像/CameraInfo 尺寸与坐标系一致性；提供板规格后，检测角点并保存其像素坐标到输出 JSON。
角点检测成功不等于内参准确，不等于手眼完成。程序不会自动将任何 commissioning 字段改成 verified。
手眼求解与独立验证已实现于 `scripts/realman/solve_handeye.py`，复现命令见左腕结果报告。
工具/关节标定仍需单独实施。

验收时分别查看重投影误差、独立姿态的板位姿闭环残差、重复采样稳定性，以及工作区内的独立实物对齐。
只有训练姿态误差小仍不足以通过；后续毫米级插入也不能仅凭单帧深度或小重投影误差放行。
